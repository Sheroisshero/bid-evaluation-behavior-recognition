# 多模态融合方案

> 本文档详细描述视频+音频+系统日志三路数据融合的异常行为识别方案，包括数据对齐、融合策略、决策算法和误报控制机制。

---

## 一、多模态融合架构

系统突破传统单一视频监控的局限，构建**三路数据融合**的多模态异常行为识别架构：

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  视频通道    │  │  音频通道    │  │  日志通道    │
│             │  │             │  │             │
│ YOLOv8检测  │  │ Whisper转写 │  │ 操作日志采集 │
│ SlowFast识别│  │ AC自动机匹配│  │ 规则引擎检测 │
│ 人脸关键点   │  │ 声纹分离    │  │ 网络状态监控 │
│ 多目标跟踪   │  │ 语义理解    │  │ 设备状态监控 │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────────────┼────────────────┘
                        ▼
              ┌─────────────────┐
              │  时间戳对齐模块   │
              │  (毫秒级精度)    │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │ 置信度加权融合引擎│
              │ (动态权重调整)   │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │  交叉验证与消歧  │
              │ (降低误报率)    │
              └────────┬────────┘
                       ▼
              ┌─────────────────┐
              │ 异常等级判定输出  │
              │ (黄/橙/红三级)  │
              └─────────────────┘
```

## 二、三路数据通道详解

### 2.1 视频通道

**检测内容：**
- 操作手机：手机目标检测 + 手部关键点 + 低头姿态
- 起身离席：座位区域人体检测 + 持续时间
- 交头接耳：多人距离 + 朝向判定 + 嘴部运动
- 肢体遮挡面部：手部位置 + 人脸关键点
- 长时间静止/走神：姿态估计 + 头部运动 + 视线方向

**技术方案：**
- 目标检测：YOLOv8（人体、手机、人脸、手部）
- 时序行为识别：SlowFast网络
- 人脸关键点：MediaPipe（68个关键点）
- 姿态估计：MediaPipe Pose
- 多目标跟踪：DeepSORT

**输出：**
- 异常类型、置信度、发生时间、持续时长
- 涉及专家ID（座位号/跟踪ID）
- 视频截图和片段引用
- 检测依据（使用了哪些特征）

### 2.2 音频通道

**检测内容：**
- 核心违禁词：放水、抬分、压分、改分等
- 敏感信息泄露：内定、指定、推荐、选这家等
- 倾向性言论：这家不行、那家好、肯定行等
- 非正常评价：凭经验、随便打分、不用看细则等
- 私下交谈：麦克风关闭时的语音能量异常

**技术方案：**
- 语音转文字：Whisper-large-v3中文模型
- 违禁词匹配：AC自动机多模式匹配
- 声纹分离：说话人分离（Speaker Diarization）
- 语义理解：大语言模型辅助上下文消歧

**输出：**
- 违禁词、类别、严重等级、匹配位置
- 发言人ID（声纹识别/麦克风通道）
- 转写文本（高亮违禁词）
- 语义判定置信度
- 音频片段引用

详见：[sensitive-word-library.md](sensitive-word-library.md)

### 2.3 系统日志通道

**检测内容：**
- 网络异常：卡顿、掉线、音视频中断
- 操作异常：异常登录、权限越界、批量导出
- 设备异常：摄像头遮挡、麦克风关闭、终端离线
- 评审环节异常：非工作时段操作、异常打分行为

**技术方案：**
- 日志采集：系统操作日志实时采集
- 规则引擎：基于预定义规则检测异常模式
- 网络监控：实时监控网络延迟、丢包率、连接状态
- 设备监控：监控摄像头、麦克风、终端在线状态

**输出：**
- 异常类型、发生时间、持续时长
- 涉及设备/用户ID
- 日志记录原文
- 异常等级判定

## 三、时间戳对齐

### 3.1 对齐策略

三路数据采用**毫秒级精度时间戳对齐**：

- **视频帧时间戳**：每帧视频带精确采集时间（NTP同步）
- **音频片段时间戳**：每个音频片段带开始和结束时间
- **日志事件时间戳**：每条系统日志带精确发生时间

### 3.2 时间窗口

融合判定采用**滑动时间窗口**：

- 窗口大小：±2秒（异常行为发生前后各2秒）
- 滑动步长：500ms
- 同一异常行为在时间窗口内的多路检测结果进行融合

### 3.3 时钟同步

- 所有设备通过NTP协议同步时钟
- 同步精度：≤10ms
- 定期校准：每小时同步一次
- 异常检测：时钟偏差>50ms时触发告警

## 四、置信度加权融合

### 4.1 融合决策公式

```
final_score = w_video × video_score + w_audio × audio_score + w_log × log_score
```

其中各通道权重根据异常类型动态调整：

| 异常类型 | w_video | w_audio | w_log | 说明 |
|---------|---------|---------|-------|------|
| 操作手机 | 0.7 | 0.1 | 0.2 | 主要靠视频检测，日志辅助 |
| 起身离席 | 0.8 | 0.0 | 0.2 | 纯视频+设备状态检测 |
| 交头接耳 | 0.5 | 0.4 | 0.1 | 视频+音频双重验证 |
| 不当言论 | 0.1 | 0.8 | 0.1 | 主要靠音频检测，视频辅助 |
| 网络异常 | 0.1 | 0.1 | 0.8 | 主要靠日志检测 |
| 设备异常 | 0.3 | 0.2 | 0.5 | 日志为主，视频音频辅助 |

### 4.2 单通道置信度计算

**视频通道置信度：**
```
video_score = 0.4 × detection_confidence + 0.3 × tracking_stability + 0.3 × duration_ratio
```
- detection_confidence：目标检测模型输出置信度
- tracking_stability：多目标跟踪的稳定性（跨帧一致性）
- duration_ratio：实际持续时长与阈值的比值

**音频通道置信度：**
```
audio_score = 0.5 × match_confidence + 0.3 × semantic_confidence + 0.2 × speaker_confidence
```
- match_confidence：违禁词匹配置信度
- semantic_confidence：语义理解判定置信度
- speaker_confidence：声纹识别置信度

**日志通道置信度：**
```
log_score = rule_match_score  # 规则引擎匹配得分
```

### 4.3 异常等级判定

根据final_score判定异常等级：

| final_score | 异常等级 | 预警等级 |
|-------------|---------|---------|
| 0.3 - 0.5 | 疑似异常 | 🟡 黄色预警 |
| 0.5 - 0.7 | 确认异常 | 🟠 橙色警示 |
| ≥ 0.7 | 严重异常 | 🔴 红色警报 |
| < 0.3 | 正常 | 不触发 |

## 五、交叉验证与误报控制

### 5.1 多通道交叉验证

为降低误报率，系统设计了多层交叉验证机制：

**规则1：单一通道高置信度 + 其他通道无矛盾 → 确认**
- 例：音频检测到"改分"（高置信度），视频无矛盾行为 → 确认不当言论

**规则2：单一通道中等置信度 + 其他通道辅助验证 → 确认**
- 例：视频检测到操作手机（中等置信度）+ 日志检测到屏幕亮屏 → 确认操作手机

**规则3：单一通道低置信度 + 其他通道无验证 → 标记为疑似，不立即预警**
- 例：视频检测到疑似交头接耳（低置信度）+ 音频未检测到私下交谈 → 标记疑似，持续观察

**规则4：通道间矛盾 → 降级处理**
- 例：音频检测到倾向性词汇，但视频显示专家在正常讨论（有依据）→ 语义消歧后可能降级或取消

### 5.2 语义消歧

针对音频通道的误报，使用大语言模型进行上下文语义消歧：

- **正常讨论场景**："这个参数不符合要求，所以这一项不行" → 有依据的否定，不触发
- **违规言论场景**："这家不行，不用看了" → 无依据的简单否定，触发
- **引用场景**："评审细则里说不行的情况包括..." → 引用规则，不触发
- **讨论场景**："大家讨论一下这个方案行不行" → 正常讨论，不触发

详见：[sensitive-word-library.md](sensitive-word-library.md)

### 5.3 评审环节上下文

结合评审环节信息进一步降低误报：

| 评审环节 | 行为容忍度 | 说明 |
|---------|-----------|------|
| 集体讨论 | 高 | 正常交流、讨论不判定为交头接耳 |
| 独立打分 | 低 | 应保持安静，任何交流都需关注 |
| 澄清环节 | 中 | 允许与供应商沟通，但需记录 |
| 休息时间 | 不监控 | 休息时段不进行异常行为检测 |
| 报告生成 | 中 | 允许讨论，但需关注不当言论 |

### 5.4 人工复核闭环

- 橙色及以上预警支持人工复核
- 复核结果（确认违规/误报）反馈用于模型优化
- 定期分析误报案例，调整检测阈值和规则
- 对高频误报词汇增加上下文约束条件

```json

  "event_type": "操作手机",
  "event_category": "视频异常",
  "severity": "中",
  "alert_level": "橙色警示",
  "confidence": 0.78,
  "start_time": "2026-08-31 14:23:15.123",
  "end_time": "2026-08-31 14:23:18.456",
  "duration_seconds": 3.3,
  "expert_id": "EXPERT-03",

    "video_clip": "video/clips/EVT-0001.mp4",

    "audio_clip": "audio/clips/EVT-0001.wav",

    "log_score": 0.65
  },

  "is_escalated": false,
  "is_verified": false,
  "verification_result": null

```

### 6.2 证据包生成

对于橙色及以上预警，自动生成**证据包**：

- 异常行为发生前后各10秒的视频片段（含音频）
- 异常发生瞬间的高清截图（标注检测框和关键点）
- 音频转写文本（高亮违禁词和上下文）
- 系统日志记录（相关时间段的所有日志）
- 融合决策详情（各通道得分、权重、判定依据）
- 时间线（异常行为的完整时间线）

证据包加密存储，支持一键导出，为监管和调查提供完整证据链。
