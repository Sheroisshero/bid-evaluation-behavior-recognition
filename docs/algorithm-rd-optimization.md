## 二、视频行为识别算法研发

### 2.1 问题定义与挑战

**任务定义：** 从远程异地评标现场的视频流中，实时检测和识别评审专家的异常行为，包括操作手机、起身离席、交头接耳、肢体遮挡面部等。

**核心挑战：**

| 挑战 | 具体描述 | 影响 |
|------|---------|------|
| 小目标检测 | 手机在画面中占比小（通常<5%画面面积） | 漏报率高 |
| 遮挡问题 | 专家之间互相遮挡，手部动作被身体遮挡 | 检测不完整 |
| 类间相似性高 | 正常操作（喝水、拿笔）与操作手机姿态相似 | 误报率高 |
| 实时性要求 | 端到端延迟≤200ms，需在边缘设备上运行 | 模型复杂度受限 |
| 光照变化 | 评标室光照不均匀，存在逆光、阴影 | 特征不稳定 |
| 视角固定 | 摄像头角度固定，缺乏多视角信息 | 行为判别困难 |

### 2.2 模型选型与对比

- 两级部署策略：边缘端初筛 + 服务器端精筛，兼顾速度和精度

### 2.3 数据工程

#### 2.3.1 数据集构建

由于评标场景的特殊性，公开数据集中缺乏直接可用的评标异常行为数据，我们采用**多源数据融合**策略构建训练数据集：

| 数据来源 | 数据量 | 标注方式 | 用途 |
|---------|--------|---------|------|
| 评标室历史监控视频 | 200小时 | 人工标注+半自动标注 | 主训练集（场景适配） |
| 公开行为数据集（AVA/Kinetics） | 50万帧 | 预标注 | 预训练+迁移学习 |
| 手机使用行为数据集 | 5万张 | 人工标注 | 小目标检测增强 |
| 合成数据（3D渲染） | 10万帧 | 自动标注 | 稀有行为增强（交头接耳等） |
| 数据增强生成 | 20万帧 | 自动生成 | 泛化能力提升 |

**总训练数据规模：** 约80万帧标注图像 + 200小时视频片段

#### 2.3.2 标注体系

采用**多级标注体系**，确保标注质量：

1. **目标级标注**：人体、手机、人脸、手部的边界框（bbox）
2. **关键点标注**：人脸68个关键点、人体17个关键点、手部21个关键点
3. **行为级标注**：每3秒一个行为标签（正常/操作手机/离席/交头接耳/其他）
4. **事件级标注**：异常行为事件的起止时间、严重等级、涉及专家

**标注质量控制：**
- 双盲标注：两名标注员独立标注，不一致时由第三人仲裁
- 标注一致性：目标检测IoU≥0.7，行为分类Kappa≥0.8
- 抽检机制：每周抽检10%标注数据，错误率>5%则全量返工

### 2.4 训练策略

#### 2.4.1 两阶段训练

**第一阶段：通用预训练**
- 在COCO+Kinetics+AVA等公开数据集上预训练
- 学习率：1e-3 → 1e-4（余弦退火）
- 训练轮次：100 epochs
- 目标：学习通用的人体、手机、动作特征

**第二阶段：场景微调**
- 在评标场景数据集上微调
- 学习率：1e-4 → 1e-5（warmup+余弦退火）
- 训练轮次：50 epochs
- 冻结策略：前10轮冻结backbone，只训练检测头；后40轮全网络微调
- 目标：适配评标场景的特殊视角、光照、行为模式

#### 2.4.2 损失函数设计

针对多任务学习（目标检测+关键点+行为分类），设计**多任务加权损失**：

```
L_total = λ_det × L_detection + λ_kp × L_keypoint + λ_act × L_action + L_aux

其中：
- L_detection = CIoU_loss(bbox) + BCE_loss(classification) + DFL_loss(box_distribution)
- L_keypoint = Wing_loss(keypoints)  # 对小误差更敏感的关键点损失
- L_action = Focal_loss(action_class)  # 解决类别不平衡
- L_aux = 0.1 × L_contrastive  # 对比学习辅助损失，提升特征判别力

权重设置：λ_det=1.0, λ_kp=0.5, λ_act=0.8
```

**类别不平衡处理：**
- 异常行为样本占比仅约15%，采用Focal Loss（γ=2.0, α=0.25）
- 对稀有类别（交头接耳、传递物品）进行过采样（oversampling）
- 类别权重：正常:操作手机:离席:交头接耳:其他 = 0.3:1.0:0.8:1.5:1.2

#### 2.4.3 优化器与超参数

| 超参数 | 预训练阶段 | 微调阶段 |

| 优化器 | SGD + momentum | AdamW |

### 2.5 模型优化与压缩

为满足边缘设备实时推理需求，采用**模型压缩四步法**：

#### 第一步：知识蒸馏（Knowledge Distillation）

```
教师模型：YOLOv8m（服务器端，mAP=94.3%）
学生模型：YOLOv8n（边缘端，mAP=89.5%）

蒸馏损失：
L_kd = α × L_hard(student, ground_truth) + β × L_soft(student, teacher)

其中：
- L_hard：学生模型与真实标签的硬标签损失
- L_soft：学生模型与教师模型的软标签损失（KL散度，温度T=4）
- α=0.3, β=0.7（软标签权重更高，充分利用教师知识）

蒸馏效果：学生模型mAP从89.5%提升至92.8%，提升3.3个百分点，接近教师模型
```

#### 第二步：结构化剪枝（Structured Pruning）

- **通道剪枝**：基于BN层缩放因子γ的L1正则化，剪枝γ<阈值的通道
- **层剪枝**：移除对精度影响小的冗余层（如backbone中的部分残差块）
- **剪枝比例**：通道剪枝30%，层剪枝10%
- **剪枝后微调**：在原学习率的1/10下微调20轮，恢复精度
- **效果**：参数量减少35%，推理速度提升25%，mAP下降<0.5%

#### 第三步：量化（Quantization）

- **量化方案**：INT8对称量化（权重）+ 动态量化（激活）
- **量化感知训练（QAT）**：在训练中模拟量化噪声，提升量化后精度
- **校准数据集**：1000张代表性评标场景图像
- **效果**：模型体积减少75%，推理速度提升40%，mAP下降<1.0%

#### 第四步：算子融合与编译优化

- **算子融合**：Conv+BN+ReLU融合为单个算子，减少内存访问
- **TensorRT编译**：使用TensorRT对模型进行层融合、内核自动调优
- **效果**：推理速度再提升30%，端到端延迟从80ms降至45ms

#### 优化前后对比

| 指标 | 原始YOLOv8n | 蒸馏后 | 剪枝后 | 量化后 | TensorRT优化 |
|------|------------|--------|--------|--------|-------------|
| mAP@0.5 | 89.5% | 92.8% | 92.3% | 91.5% | 91.5% |
| 参数量 | 3.2M | 3.2M | 2.1M | 2.1M | 2.1M |
| 模型体积 | 12.8MB | 12.8MB | 8.3MB | 2.1MB | 2.1MB |
| 推理延迟(CPU) | 120ms | 120ms | 85ms | 50ms | 35ms |
| 推理延迟(Jetson) | 28ms | 28ms | 20ms | 12ms | 8ms |
| FPS(Jetson) | 35 | 35 | 50 | 83 | 125 |

**最终边缘部署模型：** mAP=91.5%，延迟=8ms（Jetson），FPS=125，完全满足≤200ms的实时性要求。

## 三、音频敏感词监测算法研发

### 3.1 问题定义与挑战

**任务定义：** 对评标现场的音频流进行实时语音转文字，并检测其中的违规言论（四大类违禁词），同时进行说话人分离和语义消歧。

**核心挑战：**

| 挑战 | 具体描述 | 影响 |
|------|---------|------|
| 远场语音识别 | 麦克风距离专家1-3米，存在混响和噪声 | ASR准确率下降 |
| 多人同时说话 | 集体讨论时多人同时发言，语音重叠 | 声纹分离困难 |
| 专业术语 | 政府采购领域专业术语多，通用ASR模型不熟悉 | 术语识别错误 |
| 口音方言 | 专家来自不同地区，存在口音和方言 | 识别准确率波动 |
| 语义歧义 | "不行""不好"等词在正常讨论中也会出现 | 误报率高 |
| 实时性要求 | 端到端延迟≤1秒，需在边缘设备运行 | 模型复杂度受限 |

### 3.2 ASR模型选型与优化

#### 3.2.1 模型对比

### 3.3 违禁词匹配算法

#### 3.3.1 算法选型对比

| 算法 | 时间复杂度 | 空间复杂度 | 多模式匹配 | 适合词库规模 | 选型 |
|------|----------|----------|----------|------------|------|
| 朴素匹配 | O(n×m) | O(1) | 否 | <10词 | 不适用 |
| KMP | O(n+m) | O(m) | 否 | 单词 | 不适用 |
| 正则表达式 | O(n×m) | O(m) | 有限 | <50词 | 句式匹配 |
| AC自动机 | O(n+m+z) | O(m×k) | 是 | 任意规模 | **首选** |
| Wu-Manber | O(n/m) | O(m) | 是 | 大规模 | 备选 |

**选型决策：** AC自动机（Aho-Corasick），支持多模式线性时间匹配，适合55个违禁词+10条句式的实时匹配需求。

#### 3.3.2 AC自动机实现要点

```
AC自动机构建流程：
1. 构建Trie树：将所有违禁词插入Trie树，每个词的终止节点标记输出
2. 构建失败指针：BFS遍历，每个节点的失败指针指向最长后缀匹配节点
3. 输出合并：每个节点的输出包含自身输出+失败指针节点的输出

匹配流程：
1. 从根节点开始，逐字符遍历文本
2. 当前字符在子节点中存在 → 移动到子节点
3. 不存在 → 跟随失败指针，直到找到匹配或回到根节点
4. 每到达一个节点，输出该节点的所有匹配词
5. 时间复杂度：O(n + z)，n为文本长度，z为匹配次数
```

#### 3.3.3 模糊匹配与容错

为应对ASR转写错误（同音字、近音字），设计了**容错匹配机制**：

- **拼音匹配**：将违禁词和转写文本都转换为拼音，进行拼音匹配
- **编辑距离匹配**：允许1个字符的编辑距离（插入/删除/替换）
- **同音字替换**：构建常见同音字表，匹配时尝试同音字替换
- **置信度加权**：精确匹配置信度1.0，模糊匹配置信度0.7-0.9

**效果：** 因ASR转写错误导致的违禁词漏报率从8.5%降至2.1%。

### 3.4 声纹分离算法

#### 3.4.1 说话人分离（Speaker Diarization）

**技术方案：** 基于NeMo的说话人分离流水线

```
说话人分离流水线：
1. 语音活动检测（VAD）：检测语音段和静音段
   - 模型：MarbleNet VAD
   - 输出：语音段的起止时间

2. 说话人嵌入提取：对每个语音段提取说话人特征向量
   - 模型：TitaNet（说话人验证模型）
   - 输出：192维说话人嵌入向量

3. 聚类：将相似的语音段聚类到同一说话人
   - 算法：凝聚层次聚类（AHC）
   - 距离度量：余弦距离
   - 阈值：0.5（可调）

4. 重叠语音处理：检测多人同时说话的重叠段
   - 模型：重叠语音检测模型
   - 处理：重叠段标记为"多人说话"，不进行单人违禁词归因
```

**性能指标：**
- DER（说话人错误率）：8.2%（评标场景，4-5人）
- 说话人数估计准确率：92%
- 单人语音段归因准确率：95%

#### 3.4.2 麦克风阵列波束成形

对于专用型评标场所的麦克风阵列，采用**波束成形技术**增强目标方向语音：

- **算法**：延迟求和波束成形（Delay-and-Sum）+ 自适应噪声抑制
- **阵列配置**：4麦线性阵列，间距4cm
- **效果**：目标方向语音增强6-8dB，环境噪声抑制15dB
- 结合声纹分离，可更精准地定位违规言论的发言人

### 3.5 语义消歧算法

#### 3.5.1 问题分析

违禁词检测的最大挑战是**语义歧义**：

```
违规场景："这家不行，不用看了" → 无依据的简单否定，触发预警
正常场景："这个参数不符合要求，所以这一项不行" → 有依据的否定，不触发

违规场景："肯定行，直接过" → 无依据的绝对化肯定，触发预警
正常场景："这个方案肯定行，因为满足了所有技术要求" → 有依据的肯定，不触发
```

#### 3.5.2 大语言模型语义消歧

**技术方案：** 使用轻量级大语言模型进行上下文语义理解

```
语义消歧Prompt（脱敏版）：
你是一个政府采购评审合规检测助手。请判断以下评审发言中是否包含违规言论。

违规言论类型：
1. 核心违禁词：放水、抬分、压分、改分等直接干预评审结果的言论
2. 敏感信息泄露：内定、指定、推荐某供应商等
3. 倾向性言论：无依据地肯定或否定某供应商
4. 非正常评价：不按评审标准，凭经验或个人偏好评价

发言内容："{transcript}"
检测到的违禁词："{sensitive_word}"

请判断：
1. 这句话是否有评审标准或事实依据？
2. 这句话是否针对特定供应商表达了无依据的倾向？
3. 这句话是否属于违规言论？

输出格式：
{
  "has_evidence": true/false,
  "is_tendentious": true/false,
  "is_violation": true/false,
  "confidence": 0.0-1.0,
  "reason": "判断理由"
}
```

**模型选型：**
- 边缘端：Qwen-1.8B（INT4量化，推理速度~50token/s）
- 服务器端：Qwen-7B（FP16，推理速度~30token/s）
- 选择原因：开源、中文支持好、可量化部署、推理速度满足需求

**消歧效果：**

| 指标 | 无消歧 | 规则消歧 | LLM消歧 |
|------|--------|---------|---------|
| 违禁词检测召回率 | 98.5% | 95.2% | 96.8% |
| 违禁词检测精确率 | 62.3% | 78.5% | 91.2% |
| 误报率 | 37.7% | 21.5% | 8.8% |
| F1分数 | 0.762 | 0.861 | 0.939 |

**LLM语义消歧将误报率从37.7%降至8.8%，F1分数从0.762提升至0.939。**

#### 3.5.3 规则+LLM混合消歧策略

为兼顾速度和精度，采用**两级消歧策略**：

1. **第一级：快速规则消歧**（延迟<10ms）
   - 检查上下文是否包含"不符合""不达标""参数""要求"等正常讨论关键词
   - 检查是否包含"不用看""直接""随便"等违规关键词
   - 高置信度的正常/违规直接判定，不进入LLM

2. **第二级：LLM精细消歧**（延迟~200ms）
   - 规则消歧置信度低（0.4-0.7）的案例进入LLM消歧
   - 约30%的案例需要LLM消歧
   - 整体平均延迟：0.7×10ms + 0.3×200ms = 67ms，满足≤1秒要求

## 四、多模态融合算法研发

### 4.1 融合策略设计

#### 4.1.1 融合层级对比

| 融合层级 | 融合位置 | 优点 | 缺点 | 适用场景 |
|---------|---------|------|------|---------|
| 数据层融合 | 原始数据 | 保留最完整信息 | 模态差异大，难以直接融合 | 同源数据 |
| 特征层融合 | 模型中间特征 | 信息损失小 | 需要模型联合训练，复杂度高 | 深度融合 |
| 决策层融合 | 模型输出结果 | 灵活、模块化、易实现 | 信息损失较大 | 多模型集成 |

**选型决策：** 决策层融合为主，特征层融合为辅。
- 主方案：三路独立模型输出异常事件，通过决策层融合算法综合判定
- 辅助方案：视频和音频特征在共享语义空间进行对比学习，提升跨模态一致性

#### 4.1.2 置信度加权融合

**核心公式：**

```
final_score = Σ w_i × score_i  (i ∈ {video, audio, log})

约束条件：
- Σ w_i = 1
- w_i ≥ 0

权重动态调整：
w_i = base_weight_i × reliability_i × modality_relevance_i

其中：
- base_weight_i：基础权重（根据异常类型预设）
- reliability_i：该通道当前检测的可靠性（基于模型置信度、数据质量）
- modality_relevance_i：该通道对该异常类型的相关性（如操作手机视频相关性高）
```

**不同异常类型的基础权重：**

| 异常类型 | w_video | w_audio | w_log | 说明 |
|---------|---------|---------|-------|------|
| 操作手机 | 0.70 | 0.10 | 0.20 | 视频为主，日志辅助（屏幕亮屏） |
| 起身离席 | 0.80 | 0.00 | 0.20 | 纯视频+设备状态 |
| 交头接耳 | 0.50 | 0.40 | 0.10 | 视频+音频双重验证 |
| 不当言论 | 0.10 | 0.80 | 0.10 | 音频为主，视频辅助（嘴部运动） |
| 网络异常 | 0.10 | 0.10 | 0.80 | 日志为主 |

#### 4.1.3 可靠性动态调整

每个通道的可靠性根据实时状态动态调整：

```
reliability_video = f(detection_confidence, tracking_stability, lighting_quality, occlusion_rate)
  - detection_confidence：目标检测置信度（0-1）
  - tracking_stability：跟踪稳定性（跨帧一致性，0-1）
  - lighting_quality：光照质量（基于图像亮度和对比度，0-1）
  - occlusion_rate：遮挡率（被遮挡面积比例，0-1）

reliability_audio = f(asr_confidence, snr, speaker_separation_quality, overlap_rate)
  - asr_confidence：ASR转写置信度（0-1）
  - snr：信噪比（越高越好）
  - speaker_separation_quality：声纹分离质量（0-1）
  - overlap_rate：语音重叠率（越低越好）

reliability_log = f(log_completeness, timestamp_accuracy)
  - log_completeness：日志完整性（0-1）
  - timestamp_accuracy：时间戳精度（0-1）
```

**示例：** 当视频通道光照差（lighting_quality=0.3）且遮挡率高（occlusion_rate=0.5）时，reliability_video=0.4，视频权重自动降低，更多依赖音频和日志通道。

### 4.2 交叉验证与证据链构建

#### 4.2.1 多通道交叉验证规则

```
验证规则：
1. 强确认：≥2个通道同时检测到同类异常 → 确认异常，置信度提升
2. 弱确认：1个通道高置信度检测 + 其他通道无矛盾 → 确认异常
3. 疑似：1个通道中等置信度检测 + 其他通道无验证 → 标记疑似，持续观察
4. 矛盾：通道间检测结果矛盾 → 降级处理，人工复核
5. 否定：1个通道检测 + 其他通道明确否定 → 标记为误报候选
```

#### 4.2.2 证据链构建

对于每个确认的异常事件，自动构建**多模态证据链**：

```
证据链结构：
{
  "event_id": "EVT-0001",
  "event_type": "操作手机",
  "timestamp": "2026-08-31 14:23:15",
  "duration_seconds": 3.5,
  "expert_id": "EXPERT-03",

  "video_evidence": {
    "detection_confidence": 0.88,
    "bbox": [x1, y1, x2, y2],
    "keypoints": {...},
    "snapshot_ref": "video/snapshots/EVT-0001.jpg",
    "clip_ref": "video/clips/EVT-0001.mp4",
    "tracking_id": "TRK-042"
  },

  "audio_evidence": {
    "transcript": "（无相关语音）",
    "sensitive_words": [],
    "speaker_id": null,
    "audio_clip_ref": null
  },

  "log_evidence": {
    "screen_brightness_change": "2026-08-31 14:23:14",
    "device_orientation": "portrait",
    "log_records": [...]
  },

  "fusion_result": {
    "final_score": 0.82,
    "channel_scores": {"video": 0.88, "audio": 0.10, "log": 0.65},
    "channel_weights": {"video": 0.70, "audio": 0.10, "log": 0.20},
    "alert_level": "橙色警示",
    "verification": "弱确认（视频高置信度+日志辅助）"
  }
}
```

### 4.3 跨模态对比学习

为提升多模态融合的一致性，设计了**跨模态对比学习**辅助任务：

```
对比学习目标：
- 正样本对：同一时间段、同一专家的视频特征和音频特征（如说话时的嘴部运动+语音）
- 负样本对：不同时间段或不同专家的视频特征和音频特征

损失函数：InfoNCE Loss
L_contrastive = -log[ exp(sim(v_i, a_i)/τ) / Σ exp(sim(v_i, a_j)/τ) ]

其中：
- v_i：视频特征（SlowFast池化特征）
- a_i：音频特征（Whisper编码器特征）
- sim：余弦相似度
- τ：温度参数（0.07）

训练方式：在模型微调阶段，将对比学习损失作为辅助损失（权重0.1）
效果：跨模态特征一致性提升，融合决策的置信度校准更准确
```

## 六、工程化部署

### 6.1 边缘-云端协同架构

```
边缘端（MAXHUB终端/评标电脑）：
- 模型：YOLOv8n（INT8量化）+ Whisper-base（INT8量化）
- 功能：实时初筛、简单异常检测、基础违禁词匹配
- 延迟：视频45ms + 音频300ms = 345ms
- 仅传输：异常片段+特征数据（不传输完整音视频流，节省带宽）

服务器端（集中运算）：
- 模型：YOLOv8s + SlowFast + Whisper-small + Qwen-7B
- 功能：复杂行为识别、多模态融合、语义消歧、报告生成
- 延迟：融合120ms + 消歧200ms = 320ms
- 处理：边缘端上报的疑似异常，进行精筛和确认
```

### 6.2 模型服务化

- **推理框架**：ONNX Runtime（边缘端）+ TensorRT（服务器端）
- **服务框架**：Triton Inference Server（模型版本管理、动态批处理、并发调度）
- **模型热更新**：支持不中断服务的模型版本更新
- **A/B测试**：支持新旧模型并行运行，对比性能指标
- **自动扩缩容**：根据并发评审数量自动调整推理实例数

### 6.3 持续学习与模型迭代

```
持续学习流水线：
1. 数据收集：线上运行的误报/漏报案例自动收集
2. 人工标注：监管人员复核确认，标注正确结果
3. 数据筛选：筛选高质量样本加入训练集
4. 模型微调：在新数据上进行增量微调（低学习率，少轮次）
5. 离线评估：在测试集上评估新模型性能
6. 灰度发布：新模型先在10%流量上运行，对比指标
7. 全量发布：指标达标后全量替换旧模型

迭代周期：每季度一次大版本更新，每月一次小版本热更新
```
